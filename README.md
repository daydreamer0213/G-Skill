# G-Skill

一套个人 AI 协作 Skill，覆盖项目推进、产品验收、用户表达、学习讲解、历史决策整理和视频创作。

这些规范帮助 AI 根据实际任务作出判断：把用户需要的内容讲清楚，交付可以使用的结果，用实际证据判断进展，在达到可接受标准后及时完成当前阶段。

## 有哪些 Skill

| Skill | 适合什么时候用 | 主要解决什么 |
| --- | --- | --- |
| [面向用户的表达与内容交付](skills/user-facing-content/SKILL.md) | 写指南、功能说明、界面文案或其他用户材料 | 内容贴合读者任务，解释具体，层次清楚，减少无用责任切割 |
| [是，首相！](skills/yes-prime-minister/SKILL.md) | 汇报项目进度、问题、风险与结果 | 先说结论和影响，保留判断依据，在关键节点回顾总体目标 |
| [项目推进与验收](skills/supervising-evidence-led-projects/SKILL.md) | 推进较长、多阶段的开发项目 | 结合现实确定设计与判断尺度，控制范围，以证据验收并及时收口 |
| [真实使用流程审查](skills/natural-product-journey-review/SKILL.md) | 检查产品是否真正好用 | 从用户入口走到结果，检查材料、动作、异常恢复和后续操作 |

## 怎样使用

每个 Skill 是一个独立文件夹。`SKILL.md` 是入口；有 `references` 时，里面保留按需阅读的案例和专项说明。

以 Codex 为例：

1. 点击仓库的 **Code → Download ZIP**，下载并解压。
2. 打开解压后的 `skills` 文件夹，将需要的整个 Skill 文件夹复制到 `%USERPROFILE%\.codex\skills\`。例如，复制后应能找到 `.codex\skills\user-facing-content\SKILL.md`。
3. 开启新会话，输入：`使用 $user-facing-content，帮我修改这份面向用户的功能说明。`

也可以按任务名称提出要求，例如“用真实使用流程审查这项功能”。按当前任务选择适用的 Skill 即可。

## 几种常见配合方式

- **继续旧项目：** 先核对项目现状，再确定本阶段目标和验收条件。
- **审查产品体验：** 沿实际使用流程检查入口、材料、操作与结果，再修改发现的问题。
- **编写用户材料：** 先确定读者关心什么，再组织内容，完成后分别检查事实和阅读效果。
- **准备技术问答：** 先形成有主线的答案，再展开方案为什么起作用、还留下什么问题。

## 关于案例

公开案例保留问题、判断理由和适用范围，已去除本机日志路径、会话编号与个人识别信息。项目中的具体参数和历史许可用于解释当时的取舍；实际操作按当前任务和适用规则判断。

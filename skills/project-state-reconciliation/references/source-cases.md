# 去身份化状态核对案例

以下案例保留状态判断与取舍，省略原始记录、内部资料和身份信息；不是逐字引文，也不代表某个系统能力已建成。

## C08 连接设计、任务与实际状态

- **问题：**新任务继续修改旧模块，但旧设计与任务的关系逐渐失效；一份未来蓝图被当作当前状态，跨模块修改又引出应检查多大范围的问题。
- **判断与理由：**代码与运行证据说明实际能力，任务连接计划与实施，文档还需区分当前已确认基线和未来提案。未来可能插入或跳过阶段，给蓝图加日期不能把它变成当前事实。模块有关联，也不等于消费了本次变更。
- **方法：**按用户功能连接设计目标、任务、代码、版本及运行证据。由实际变更定位对应文档，再追踪哪些下游消费了变化内容；先粗定位，必要时逐层细化，同时考虑记录与检查成本。
- **适用范围：**适用于状态核对和受影响范围判断。无需预建全部细粒度依赖；“代码存在”与“该版本运行已验证”分别表达，当前核对不等于已实现自动同步。

## C09 保存决定状态，再做适量交接

- **问题：**讨论中的新答案未落到已有设计，后来实现与印象不一致；候选方案的试验成功又容易被误认为正式切换。为防遗漏，每个小问题另建文档也造成负担。
- **判断与理由：**方向已交给执行者时，细节可继续设计，但新建议、已确认决定和已实施状态要分开。讨论成熟后汇总到对应资料，比不断创建独立文档更易维护；交接还需解释为何这样做。
- **方法：**标明正式路线、试验候选、批准试用和暂未采用项，说明对照对象和本次比较的问题。获得更新任务后，把决定、理由和范围补进已有文档；交接携带目标、状态、角色、证据和下一步。
- **适用范围：**适用于设计讨论、方案比较与交接。某次“先审内容再落文档”的约定不自动变成所有任务的额外审批；候选成功不证明已经启用，旧方案也不应在每次交接中无依据地重新推荐。

## C19 按用途保存与压缩记录

- **问题：**长期对话把编码细节、旧计划、用户要求与当前状态混在一起；若全量加载，重要要求易被淹没，若一律删除历史，又失去决策依据。
- **判断与理由：**临时工作细节、随阶段失效的计划、稳定要求和可复用方法具有不同用途。较新决定可能基于新状态，既不能被旧决定阻碍，也不应抹去变化原因；错误召回也可能比缺失更误导使用。
- **方法：**先压缩可再现的工作细节，将完成或失效计划转为带时间的历史，保留要求及关键决定的依据；区分当前状态、历史经历、稳定偏好和任务方法，按本次问题检索。
- **适用范围：**适用于长期记录与交接材料维护。选择性保存和按需检索不代表已经拥有后台索引、自动记忆或跨会话同步能力；学习作答与探索假设仍须标明性质。

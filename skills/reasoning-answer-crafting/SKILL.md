# 把答案与教学说明分开

## 成稿流程

1. 确认问题在问什么、希望改善什么、限制是什么。原题有歧义时先澄清影响答案的歧义。
2. 形成最终答案。独立笔记先保留题目或一句目标摘要，已有题干则无需重复。先给总判断，再归纳少量主要方向，每个方向用主句连接具体措施和作用；最后说明怎样配合及结果条件。
3. 单独写教学性的解题说明。列一个合理起点，说明它解决的部分，再指出留下的真实缺口，用这个缺口引出下一方向。直到覆盖原题主要目标。
4. 检查两段对应。每个最终方向有清楚理由；教学说明不只是换词重复结论，也不凭空制造缺陷来硬凑两个方向。
5. 按用户用途压缩。面试答案可概括，学习说明可展开。需要用户先审内容再落文档时遵循该次约定；不推为所有任务的额外审批。

“解题说明”是面向读者的概念、假设、取舍和可验证依据，不是逐字披露模型内部思维过程。不要把整理后的教学叙述冒充实际发生的隐藏推理。

## 简短示例

等待问题可以分为“及时给真实进度反馈”和“减少实际处理耗时”。反馈帮助用户知道任务在推进，但并未减少计算；再按耗时所在环节选优化方法。具体性能目标由测量支撑，例题里的“两秒”不自动变成产品保证。

## 验收

- 零上下文读者能找到问题、总判断和主要方向。
- 说明呈现方案覆盖范围与补充理由，而不是简单列知识点。
- 表达自然且主线保留，减少机械套话不等于消除必要层级。

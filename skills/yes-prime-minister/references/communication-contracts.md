# Communication Contracts

先选择一个主要目的。多个目的并存时，先写对用户判断影响最大的一个。

| 目的 | 用户需要获得的信息 |
|---|---|
| 方向确认 | AI 对目标的理解、最终结果、重要边界或假设、第一步行动 |
| 有效进展 | 已改变的项目状态、支持证据、核心流程状态、距离可交付的缺口、总体方向和下一检查点；不罗列操作记录 |
| 问题或风险 | 问题、实际影响、已确认与待确认原因、处理方案、用户是否介入 |
| 请求决定 | 决定事项、为什么现在决定、各选项后果、推荐及依据、等待期间能否继续 |
| 阻碍 | 无法完成的部分、准确原因、已排除内容、缺少的输入或权限、已完成的安全工作 |
| 最终完成 | 完成/部分完成/未完成、用户可见变化、核心流程端到端证据、验证、偏差、剩余风险、下一步、必要的恢复方式 |

任务已经明确时直接开始，不为形式要求确认。只有选择会明显改变结果、风险、成本或权限时才请求用户决定，并给出推荐。

## Example

技术事实：登录改动的 52 项检查中 47 项通过，5 项自动续期检查失败，原因是程序使用新缓存接口而测试仍模拟旧接口。

目标表达：

> 目前只完成了一部分，还不能交付。
>
> 登录主流程已经改好，但“自动延长登录状态”仍有 5 项检查失败。如果现在上线，用户可能在使用一段时间后被意外退出。
>
> 问题已经定位到缓存接口不一致。缓存就是临时保存登录状态的部分；程序已经改用新的调用方式，但测试仍在模拟旧方式。
>
> 我会先统一这两处接口，再重新运行全部 52 项检查。全部通过前，我不会把任务标记为完成。你现在不需要操作。

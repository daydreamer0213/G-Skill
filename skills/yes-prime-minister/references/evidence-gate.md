# Evidence Gate

## Fact Record

Before writing a user-visible project message, internally record only:

- FACTS: exact object | exact status | direct support
- UNKNOWNS: decision-relevant facts not proved by the input or tools
- REQUESTED WORDING: wording or conclusions someone requested but evidence does not establish

Requested wording never supplies evidence. Keep local progress separate from the user-facing or core-flow status. Do not expose this record or private reasoning.

This gate takes priority over general information responsibilities and examples in other references. When direct support is missing, omit any handling method, owner, or user-action statement they would otherwise suggest.

## Draft and Check

Generate the factual draft only from FACTS, then check every decision-relevant claim:

1. Preserve the exact object and status that the evidence supports.
2. State local progress and the user-facing or core-flow status separately.
3. Do not invent validation activity or infer schedule impact, handling methods, completion, delivery, release readiness, or safety.
4. Keep important risks and unknowns visible. State a next verification, handling method, owner, or user action only when direct evidence establishes it. Otherwise omit it: never invent a method, assign an owner, or say the user does or does not need to act.

When requested wording conflicts with evidence, state the accurate status and missing proof without repeating the unsupported conclusion as true. Without core-flow evidence, say that the core flow is unverified while preserving supported local progress.

## Presentation Boundary

Add user titles, role tone, humor, and praise only after the factual draft passes this check. Presentation cannot change objects, states, evidence, risks, completion, or required user action. Remove humor and praise in serious incidents.

# Realistic screening and finishing a stage

整理日期：2026-10-16。以下为去身份化的实际项目案例，保留问题、判断理由与适用范围，不表示任何当前操作授权，也不表示产品已因此完成验收。

## 1. 用现实情境解释省略，用依据记录事实

用户强调：“专业并不是硬性要求，专业不符不代表绝对不匹配”；“基于实际，基于现实”；“有时候简历上有的信息没有给，是因为默认其实是有/没有”。

对照案例：正常完整简历只列已完成本科，按本科理解，不猜隐藏硕士；未额外标注全日制，不因此否掉实际工作相关的岗位；相邻工科专业加实际软件开发经历，应结合岗位工作判断相关性。三例共同反对的是脱离正常招聘情境的推理，结论不应被简化成“所有缺失都算满足”或“所有缺失都要确认”。

适用方法：看信息在真实材料中通常怎样表达，再判断当前决定是否需要更精确依据。可以保留初筛机会，同时准确记录“简历列本科”“未标注学制”；没有确认的信息不写成“已核实全日制”。简历未写城市也不能随意补城市，愿望不能记作已有能力。

## 2. 先划清阶段要决定的事

用户说：“这个模块的核心在于岗位jd的判断，而不是再一些细枝末节上面反复较真。”进一步给出标准：“真正合适的岗位不漏投，明显不合适的岗位不投”；对有匹配也有差距的岗位，“投了也无所谓，投递只是寻找机会，不是确立工作关系”。

判断理由：初筛的目标是发现有投递价值的机会；把后续资格核验全部前置，会丢掉有现实可能性的岗位。做法是先判断主体工作和相关经历，结合漏掉机会与多尝试一次的代价确定边界；明确的重要冲突仍需处理，不能把明显不同的工作混进推荐。

适用范围是当前阶段的探索与排序。最终资格确认、录用或合同等决定按各自需要的信息精度处理；真实外部沟通仍遵守具体授权。不要仅因理论上可能后续确认，就假设已经存在可用的复核流程。

## 3. 约定接受标准，也约定结束条件

用户多次要求每轮或每阶段回顾，检查是否“陷入局部追求最优的调试螺旋里面，导致项目的正常开发被拖延，进度无效推进”。

方法：阶段开始时列可检查的可接受结果和结束条件；每轮完成后看新增的可用能力、有效证据或已解决问题。标准已满足时完成本阶段，把不影响当前使用的进一步优化留给后续。只有需求变化、实际失败或会改变下一步决定的未知，才重开对应检查；没有新问题时不为措辞统一重复试验。

案例中的另一个问题是反复重新采集材料，让验证成本增加。判断理由：受控测试的小样本用于验证具体行为，不能偷换为降低正式使用的召回或资料覆盖。适用方法：优先复用已有完整材料，保留已取得的资料；新增样本覆盖本次待验证的不同情况，采集范围仍按当前项目规则与授权确定。

## 4. 历史例外不能变成当前权限

问题：项目曾调整测试限制，后续执行容易把一次安排扩大成通用许可，或在项目规则已经变化后继续沿用旧边界。

判断理由：轮次间隔、内部额度、随机访问节奏、浏览器焦点和真实外部操作分别受约束。调整其中一项不自动改变其他项；后来的明确规则覆盖旧安排，也不能假设其他检出目录已经同步。

适用方法：执行前核对当前项目仍生效的规则与授权，按操作、阶段与原因解释例外，保留未被改变的随机节奏及实际登录、风控异常停止条件。具体额度、休息时长、焦点规则和试验权限留在对应项目规则中。本案例不授权外部发送，也不授权重试结果不明确的操作。

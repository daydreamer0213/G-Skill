# 用问题和场景教会一个概念

1. 确认学习目标、已懂内容和当前困惑。材料中已有答案就直接利用，避免重复询问。
2. 说明为什么需要它。给一个不使用该机制会遇到的具体问题，而不是先列定义。
3. 用生活类比建立直觉。点明哪些关系相似；会误导下一步理解的差异也说清楚。
4. 解释原理。沿着同一例子说明输入、发生的步骤、输出及关键条件。术语在第一次出现时解释。
   先核对题目中概念的准确含义，区分容易混淆的邻近概念；类比和简化不能把不同机制合成一个定义。不确定的技术结论查可靠资料，再用简单表达讲清；不为核对术语无限扩展课程。
5. 展示具体用法。给可跟随的操作或完整小例子，让学习者看出原理如何影响结果。
6. 给一两道应用题。题目检验本节关键区别或方案选择，不只让用户复述定义。
7. 根据回答指出已理解的点和真正缺口，必要时换例子重讲，再进入下一小节。

单轮结束而用户尚未作答时，可收束为本节关键点与一个练习，不据此判定掌握。用户暂不做题而选择继续，可以推进并在合适位置回顾；教学支持学习，不增加强制答题关卡。

长期训练可根据题目耗时、准确率及错因调整练习和复习，再检查同类新题是否改善；课程频率与奖励形式按学习目标决定。这是训练产品设计的可选延伸，不要求每次解释概念都建设学习档案或强制周测。

一次聚焦一个可掌握单元。学习者的猜测、转述和历史作答是理解线索，不直接当作正确事实；对技术结论按任务需要核实。

验收：学习者能解释为什么需要、跟随一个用例，并在小变化的场景中应用。默认五步结构服务学习，不要求每步都加标题或把短问答写成长课。

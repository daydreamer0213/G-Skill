# Creating AI Videos

## Core principle

Create either a product video or a viewpoint video. Keep product promotion and industry judgment in separate videos. Research may be complex; the finished video should make one central idea easy to follow.

## Route the request

Always read `references/creator-profile.md`. A task-specific user instruction overrides its defaults.

- For a product introduction, demonstration, review, workflow case, or the creator's own software, read `references/product-videos.md`.
- For industry intelligence, technical history, speech analysis, trend interpretation, or personal judgment, read `references/viewpoint-videos.md`.
- For a brief, outline, planning through publishing, or work spanning multiple production stages, also read `references/production-workflow.md`.
- If a request mixes product promotion with industry opinion, propose two separate videos and continue with the part the user prioritized. When product is prioritized, keep the broader industry thesis entirely in the separate viewpoint-video idea; do not weave it into the product video's hook, main judgment, chapters, narration, or closing.
- Deliver only the requested artifact or artifacts. Do not add titles, scripts, storyboards, packaging, publishing plans, or reviews unless the user requested them.
- When a partial deliverable is usable with a lightweight assumption or editable placeholder, state it briefly and deliver instead of stopping for optional precision.

Ask one concise question only when the missing answer would materially change the video's purpose. Otherwise make a reasonable assumption and state it briefly.

## Shared requirements

- Define the target viewer, one core question, and one main judgment before expanding the content.
- Distinguish verified facts, the creator's test results, inferences, and personal opinions.
- For changing AI products, include the relevant version, date, region, plan, or test condition.
- Treat one successful screen recording as one observed result, not universal proof.
- Prefer original documents, official pages, real screen recordings, and self-made diagrams.
- Use only material the creator made, has permission or a license to use, or whose terms allow the intended use. If the authorization for footage, music, text, or graphics is unclear, replace it with original recordings, self-made visuals, or clearly permitted official material.
- Build the creator's own voice. Do not imitate another creator's wording, catchphrases, narration, scripts, or visual assets.
- Fit the default 6–12 minute scope and weekly time budget unless the user specifies otherwise.

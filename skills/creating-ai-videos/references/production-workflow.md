# Production Workflow

Load this reference for a brief, outline, work spanning multiple production stages, or an end-to-end workflow.

## 1. Brief

Write four lines before research:

- target viewer;
- video mode: product or viewpoint;
- one core question;
- one main judgment or demonstrable result.

Define the requested artifact and expected length. Do not create unrequested downstream artifacts.

When delivering a brief or outline, include the applicable format and on-camera choice from the creator profile unless the user overrides them. Keep this compact; do not expand it into an unrequested end-to-end workflow.

## 2. Research

Collect primary sources first. For changing AI products, record version, access plan, region, test date, input, settings, output, failures, and privacy-sensitive material that must not appear on screen.

For viewpoint videos, keep facts, test results, inferences, and opinions distinguishable in notes. For product videos, preserve failed attempts and limitations instead of recording only the best run.

## 3. Spoken script

Write for listening:

- short sentences;
- one idea per sentence;
- technical terms only after the viewer has a reason to need them;
- transitions that explain why the next section matters;
- one main conclusion, repeated only when it helps orientation.

Read the draft aloud. Remove material that does not change understanding, evidence, or action.

## 4. Visual plan

Map each section to the strongest available evidence:

1. real screen recording;
2. official page or original document;
3. self-made chart, timeline, or relationship map;
4. simple title card;
5. licensed decorative footage only when it materially helps.

Default to a 16:9 horizontal master. Keep subtitles to two lines where practical and make one number, term, or conclusion the visual focus of each screen.

## 5. Voice and sound

Use either human voice or AI voice, but keep pronunciation and pacing consistent. Slow down for product names, numbers, limitations, and the main judgment. Leave a short pause before or after important conclusions. Keep background music below the voice and avoid music that supplies false drama to weak evidence.

## 6. Packaging and publishing

Make product and viewpoint videos visually distinguishable. The title and cover should add information rather than repeat each other. Include sources, test conditions, relevant links, commercial disclosures, and AI-generated-content labels when applicable.

Use the horizontal master for the main release. Create 9:16 derivatives or native shorts only when requested or justified by a later platform experiment.

## 7. Ten-hour default budget

| Work | Time |
|---|---:|
| Question and research | 3.0 h |
| Outline and script | 2.0 h |
| Screen recording and visual evidence | 2.0 h |
| Voice, editing, and subtitles | 2.0 h |
| Cover, source check, publishing, and notes | 1.0 h |

Reduce scope before compressing fact-checking or limitations.

## 8. Review and Skill updates

Before publishing, verify purpose, factual support, spoken clarity, visual readability, privacy, copyright, disclosures, and call to action. After publishing, record repeated viewer questions, retention drops, saves, comments, and production bottlenecks.

Update the Skill only when a lesson repeats or proves durable. Modify the relevant reference instead of adding a chronological diary entry.
